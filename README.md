# Конфигурационное управление · ПР № 2 · вариант 9

CLI строит граф зависимостей пакета Alpine Linux выбранной версии. Он
читает поля APKINDEX напрямую из архива по HTTP(S). Поиск зависимостей
использует стандартную библиотеку Python. Pillow нужен для записи PNG.

## Установка и проверка

Нужен Python 3.10+. Сборки нет. Из папки репозитория:

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
```

На Windows активируйте виртуальную среду через
`.venv\Scripts\Activate.ps1` и запускайте `python -m src` вместо
`./run.sh`. На macOS и Linux можно использовать оба способа запуска.

## Настройки

| Опция | Назначение |
| --- | --- |
| `--package` | Имя корневого пакета. В тестовом режиме — одна буква A–Z |
| `--repo` | URL каталога архитектуры, URL APKINDEX.tar.gz или путь к тестовому файлу |
| `--test 0/1` | Реальный индекс (0, по умолчанию) или тестовый граф (1) |
| `--version` | Точная версия корня. В тестовом режиме она служит меткой вершин |
| `--output` | Имя PNG, по умолчанию graph.png. Рядом создаётся файл .mmd |
| `--ascii 0/1` | Показать ASCII-дерево при 1. По умолчанию 0 |
| `--filter` | Подстрока в имени исключаемых пакетов. Регистр учитывается |

Опции с неверным форматом возвращают код 2. Ошибки загрузки, отсутствия
версии или записи результата возвращают код 1. Родительский каталог
выходного файла должен существовать. Путь в `--repo` или `--output` для
`run.sh` считается от папки проекта.

## Примеры

Формат тестового графа — по одному пакету в строке, например `A: B C`.
Объявите и листья, например `B:`. Строки файла могут образовывать циклы.

```sh
./run.sh --test 1 --repo examples/cycle.txt --package A --version 1 \
  --output cycle.png --ascii 1
./run.sh --test 1 --repo examples/diamond.txt --package B --version 1 \
  --output branch.png --ascii 1
./run.sh --test 1 --repo examples/chain.txt --package D --version 1 \
  --output leaf.png --ascii 1
repo=https://dl-cdn.alpinelinux.org/alpine/v3.22/main/aarch64
./run.sh --repo "$repo" --package jq --version 1.8.2-r0 \
  --output jq.png --ascii 1
```

Файл .mmd можно открыть в редакторе с поддержкой Mermaid. PNG рисует
тот же граф. В ASCII-дереве повторная вершина помечается и дальше
не раскрывается. В графе при этом остаются и циклы, и общие зависимости.

## Как устроен анализ

`config.py` проверяет CLI. `apk.py` читает поля имени, версии,
зависимостей и виртуальных возможностей из APKINDEX.
`versions.py` разбирает условия версий. `graph.py` строит рёбра
и обходит их очередью BFS. `render.py` отвечает за три формата вывода.

Граф отражает кандидатов в одном индексе, включая виртуальные
возможности `so:` и `cmd:`. Узлы с `?` означают требования, для которых
в индексе нет кандидата. Записи с `!` обозначают конфликт, поэтому
для них не строится ребро зависимости. Фильтр удаляет подходящие
вершины из обхода, сохраняя выбранный корень.

## Сопоставление с Alpine

В Alpine с той же архитектурой и репозиторием можно построить эталон:

```sh
apk --repositories-file /dev/null --repository "$repo" dot 'jq=1.8.2-r0' > jq.dot
dot -Tpng jq.dot -o jq-native.png
```

Сравнивайте имена и рёбра, а не координаты на картинке. По
[документации Alpine](https://wiki.alpinelinux.org/wiki/Alpine_Package_Keeper#apk_dot)
`apk dot` выдаёт Graphviz DOT. Наш анализ выводит Mermaid и перечисляет
кандидатов из одного индекса. Он не моделирует транзакцию установки,
приоритеты нескольких репозиториев и разрешение конфликтов решателем
apk. Сравнение версий покрывает обычные числовые версии, ревизии и
суффиксы, но не гарантирует полной совместимости с правилами apk.

## История

- `stage1` — проверка и печать всех параметров. Ошибки каждой опции
  демонстрируются тестом `test_each_invalid_option`.
- `stage2` — прямые требования точной версии из Alpine APKINDEX.
- `stage3` — BFS, фильтр, циклы, тестовые графы.
- `stage4` — обратный обход. Запустите пример с `diamond.txt` для D
  и E, затем пример с `cycle.txt` для B.
- `stage5` — Mermaid, PNG и ASCII-дерево. В `main` та же версия.
