# Конфигурационное управление · ПР № 2 · вариант 9

Этап 1. Прототип CLI анализатора зависимостей Alpine. Python 3.10+.
Сборка не требуется. Запуск из каталога проекта.

```sh
./run.sh --package busybox --version 1.2-r0 --repo https://example.org
python3 -m unittest discover -s tests -v
```

`--help` показывает список опций. Прототип печатает параметры в формате
`ключ=значение`. Тесты проверяют некорректный ввод для каждой опции.

Этап 2. Для заданной версии читаем архив APKINDEX.tar.gz из указанного
каталога Alpine (либо по прямому URL) и печатаем исходное поле зависимостей.

Этап 3. `--test 1 --repo examples/cycle.txt --package A --version 1`
загружает тестовый граф. Дополнительные случаи: `diamond.txt` (общая
зависимость), `chain.txt` (цепочка и отдельный узел). `--filter B`
исключает пакеты с B в имени и не обходит их потомков через этот путь.

Этап 4. Теперь по умолчанию выводятся обратные зависимости. Пример:
`./run.sh --test 1 --repo examples/diamond.txt --package D --version 1`.
Для E зависимых пакетов нет. В `cycle.txt` обход B сохраняет цикл.
